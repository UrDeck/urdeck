UrDeck is configured by one JSON file, `urdeck-config.json`, which lives in UrDeck's data folder, `%APPDATA%\UrDeck` (choose **Open data folder** in the tray menu to open it). There is no editor
yet (it is planned); you edit the file in any text editor. UrDeck notices a saved change after about a second and applies
it without a restart. A file that is not valid JSON is ignored and the last good configuration stays in use; the reason is
written to `urdeck.log`, next to the file. The first start creates the file from the sample page. The file's `"version"` is 1; a file written by a newer UrDeck is read as well as possible but never changed.

Everything you own sits in that folder, so reinstalling or updating UrDeck never touches it: the configuration, the log, `themes/`,
`backgrounds/`, `plugins/` (plugins you add) and `cache/`. To keep it beside the program instead (on a USB stick, say), put an
empty file named `urdeck.portable` next to `UrDeck.Host.exe` and restart; that folder is then the data folder. The release's portable zip does this for itself; see [Installing and updating](/docs/installing/#the-portable-zip).

## The file

```json
{
  "pages": [
    {
      "name": "Default",
      "widgets": [
        { "typeId": "urdeck.widgets.clock", "col": 0, "row": 0, "width": 4, "height": 2, "format": "24h", "showDate": true }
      ]
    }
  ],
  "activePage": 0,
  "dock": [
    { "typeId": "urdeck.widgets.shortcut", "target": "https://github.com", "label": "GitHub" }
  ],
  "theme": "default-dark",
  "monitorName": "tallest"
}
```

| Field | Meaning |
|---|---|
| `pages` | The pages. Each has a `name` and a list of `widgets`. |
| `pages[].widgets[]` | A widget. `typeId` says which one; `col` (0 to 3), `row`, `width` (1 to 4) and `height` are in grid cells. A value out of range is clamped and a warning is logged; an unknown `typeId` leaves its place empty. Every other property is a setting of that widget (see the widget pages). |
| `activePage` | The index of the page shown at startup. Swiping does not change the file. |
| `dock` | Up to four widgets kept at the bottom of every page. See [Pages and the dock](/docs/pages-and-dock/#the-dock). |
| `theme` | the name of a built-in theme (`default-dark` is the default) or of a folder under `themes/`. See [Themes](/docs/themes/). |
| `background` | A moving background or a picture behind the cards. See [Backgrounds](/docs/backgrounds/). |
| `monitorName` | Which monitor to choose when none is remembered yet. See [The monitor](#the-monitor). |
| `providers` | Optional settings per data provider, for example `"providers": { "system": { "intervalMs": 500 } }` reads the `system` provider every 500 ms instead of every 2000 ms. See [Data providers](#data-providers), which also explains secrets. |
| `pager` | How the page indicator shows, see [Pages and the dock](/docs/pages-and-dock/#pages). |
| `motion` | How much the deck may move: `"full"`, `"reduced"` or `"off"`. Without it the deck follows Windows' Animation effects setting (off means `off`, on means `full`) and a change of that setting applies without a restart. `"full"` overrides Windows: the deck moves even with its animations off. A theme can lower the level further. Below `full`, a theme's animated border and a moving background shader are drawn still; the page slide and the press feedback are not affected. The log says `Motion: <level> (<what decided it>)`. |
| `updates` | Whether an installed copy looks for a newer release: `"auto"` (the default) or `"off"`, which makes no request. Another value is treated as `"auto"` with a warning in the log. See [Installing and updating](/docs/installing/#updating). |

## Data providers

A data provider reads something (your PC, the weather, a service of yours) for the widgets to show. Its settings are the object
`providers.<id>` in `urdeck-config.json`. Every provider has three:

| Setting | Meaning |
|---|---|
| `intervalMs` | How often the provider is read, in milliseconds. A value below the provider's minimum is raised to it. A change takes effect at once, without restarting the provider. |
| `actionTimeoutMs` | How long an action (a button on a card) may run before it fails. Default `10000`; a value below `1000` is raised to it. |
| `actionWarnMs` | An action slower than this is logged as a warning. Default `2000`. |

A provider that talks to a service of yours has more: an address, a token. Saving them in the settings window (tray icon,
Settings, Providers) writes the address to `urdeck-config.json` and the token to Windows Credential Manager. Changing a
provider's settings restarts that provider only; the others keep running.

### Secrets

A token or password is a **secret** setting. It is never written to `urdeck-config.json` or to `urdeck.log`. UrDeck looks for it
in this order and uses the first it finds:

1. The environment variable `URDECK_SECRET_<PROVIDER>_<SETTING>`: the provider's id and the setting's name in capitals, joined by
   `_`, with `.` and `-` written as `_`. The Home Assistant token is `URDECK_SECRET_HOMEASSISTANT_TOKEN`.
2. Windows Credential Manager, as a generic credential named `UrDeck/<provider>/<setting>` (for example
   `UrDeck/homeassistant/token`). It belongs to your Windows user on this PC; Control Panel's Credential Manager lists it and can
   delete it.

Every copy of UrDeck you run on the PC (installed, portable, a development build) shares the stored secrets. To give one copy a
different token, set the environment variable for that copy. If a token was saved for one address and a copy is set up for
another, the log says so (`Secret homeassistant/token: saved for https://ha.home, but url is ...`).

If you paste a token into `urdeck-config.json` by hand, UrDeck moves it to Credential Manager the next time it reads the file and
removes it from the file (the log says `Secret ...: moved from urdeck-config.json to Credential Manager`). A file from a newer
version of UrDeck is never written, so its token stays where it is and is used for that run. Without Credential Manager (Linux)
the environment variable is the only place for a secret.

The log tells where each secret came from every time a provider starts, for example
`Secret homeassistant/token: from Credential Manager`, and `missing; set it in Settings` when there is none. A secret is at most
2,560 bytes. Uninstalling UrDeck deletes every credential named `UrDeck/...`.

## The grid

The screen is a grid of four columns of square cells; a cell is a quarter of the screen's width. On the 1100 by 3840
panel a cell is 275 pixels and a 4x2 widget is 1100 by 550. Nothing in the file is in pixels, so a page looks the same
on any display; the number of rows is what the height allows.

## The monitor

UrDeck stays on one physical monitor. The first time it starts it chooses one by `monitorName` and remembers it as
`display` in the file, so the monitor you plug in later, or the order Windows numbers them in, does not move the deck.

`monitorName` is one of `"primary"`, `"tallest"` (the tallest portrait monitor, the default), `"widest"`, `"largest"`
(most pixels), or a device name such as `"DISPLAY1"`. `monitor` is a 1-based index used when the name matches nothing.

You do not edit `display`. To make UrDeck choose again, for example because the first start picked the wrong monitor
while yours was switched off, remove `display` from the file or use **Choose automatically** in Settings.

Left-click the tray icon, or right-click it and choose **Settings**, to open the settings window. It lists every
connected monitor with its name, resolution, orientation and a number, and the one the deck is on says "Deck is here".
Click a monitor to move the deck there and keep it there. **Identify** shows each monitor's number in its corner for two
seconds.

After sleep, a monitor being plugged in or out, or a change of resolution or scaling, UrDeck waits for the monitors to
settle and puts the window back on its monitor. While that monitor is not connected the deck is hidden, its widgets stop,
and the tray icon says it is waiting; it comes back by itself.

## Closing and starting

The deck window never takes focus, so touching it does not interrupt a game or another application. As a consequence
Escape does not close it: right-click the tray icon and choose **Quit**. On Windows 11 a new icon may sit in the overflow
flyout (the `^` arrow) until you drag it to the taskbar. **Start with Windows** in the same menu starts UrDeck at sign-in.

`urdeck.log` is the place to look when something is not as you expected. Each line starts with the date and time, and at
5 MB the file becomes `urdeck.log.1`.
