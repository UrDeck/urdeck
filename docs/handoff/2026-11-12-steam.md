# Steam without an API key: what the PC and a QR sign-in give

Exploration of GitHub issue #162 (a Steam provider and widgets), 2026-11-12. The issue planned the Steam Web API with a
user-made API key and a pasted SteamID. The goal here was to find a way that asks the user for neither. Results feed three
OpenSpec changes: `list-readings`, `provider-sign-in` and `steam-provider`.

## What Steam keeps on the PC (no key, no sign-in, no network)

Read on the owner's PC (Windows 11, Steam installed under `C:\Program Files (x86)\Steam`), read-only:

| Where | What | Use |
|---|---|---|
| `HKCU\Software\Valve\Steam\ActiveProcess\ActiveUser` | 32-bit account id of the signed-in user, 0 when none | Who I am: SteamID64 = id + 76561197960265728 |
| `HKCU\Software\Valve\Steam\ActiveProcess\pid` | Steam's process id | Whether Steam runs |
| `HKCU\Software\Valve\Steam\RunningAppID` | App id of the game being played, 0 when none (it held the game's id while one ran) | My game, instantly, by a registry change notification |
| `HKCU\Software\Valve\Steam\Apps\<appid>` | `Running`, `Updating`, `Installed`, sometimes `Name` (128 apps) | Running and updating flags |
| `<Steam>\config\loginusers.vdf` | Accounts that signed in here: SteamID64, account and persona name, `MostRecent` | My name; the SteamID when Steam is not running |
| `<Steam>\config\libraryfolders.vdf` | Library folders | Where the `appmanifest` files are |
| `<library>\steamapps\appmanifest_<appid>.acf` | Name, `StateFlags`, `BytesToDownload`, `BytesDownloaded`, size | Game names; download and update progress |
| `<Steam>\appcache\librarycache\<appid>\` | `header.jpg` and other capsule art | Game art without a download |
| `<Steam>\userdata\<accountid>\config\localconfig.vdf` | Per app `LastPlayed`, `Playtime`, `Playtime2wks` (206 apps); a `friends` section with cached names and avatar hashes, but no live state | Recent games and hours |

The files are Valve's text KeyValues format (VDF); `appinfo.vdf` (binary) is not needed. Friends' live state is not on disk.

## Routes considered for friends' live state

| Route | Key | Live friends | Verdict |
|---|---|---|---|
| Local files and registry | none | no | always on, for everything about me |
| `steamcommunity.com/profiles/<id>?xml=1` | none | my own state only | works (tested 2026-11-12) but deprecated; not needed |
| QR sign-in + service methods | none | **yes** | **chosen** (results below) |
| SteamKit2 session (LGPL-2.1) | none | yes, pushed | fallback if token renewal fails |
| Web API key (the issue) | user's | yes | not needed |
| Steamworks SDK | needs an AppID | yes | rejected: the user would show as playing it |
| `steamclient.dll` IPC, the client's CEF debug port | none | yes | rejected: undocumented, breaks, unsafe |

## The QR sign-in spike

A throwaway Python script (not kept) did the following against the owner's account:

1. `POST api.steampowered.com/IAuthenticationService/BeginAuthSessionViaQR/v1/` with form fields `device_friendly_name`,
   `platform_type=2` (web browser), `website_id=Community`. No key. Answer: `client_id`, `request_id`, `interval` (5 s),
   `challenge_url` (an `s.team/q/...` link: **a sign-in secret**, drawn as a QR code locally, never sent to a QR service),
   `allowed_confirmations`, `version`.
2. Polled `PollAuthSessionStatus/v1/` (`client_id`, `request_id`) every `interval`. The challenge rotated once
   (`new_client_id`; the QR content changes, so the host must redraw it). `had_remote_interaction` turns true when the
   phone has scanned.
3. After approval in the Steam mobile app: `access_token`, `refresh_token`, `account_name`. Both tokens are JWTs; `sub`
   is the SteamID64. Refresh token audience `web, renew, derive`, valid 211 days; access token audience `web`, about
   24 hours.

Which calls take `access_token` in place of a key:

| Call | Result |
|---|---|
| `ISteamUser/GetPlayerSummaries/v2` | HTTP 400 (key only) |
| `ISteamUser/GetFriendList/v1` | HTTP 400 (key only) |
| `IFriendsListService/GetFriendsList/v1` | OK: 95 entries, 88 with relationship 3 (friend) |
| `IPlayerService/GetPlayerLinkDetails/v1` (`steamids[n]`) | OK for 79 of 88 friends (the 9 missing are unexplained). `public_data`: `persona_name`, `profile_url`, `sha_digest_avatar`, `visibility_state`, `profile_state`. `private_data`: `persona_state`, `persona_state_flags`, `last_logoff_time`, `last_seen_online`, and while playing `game_id`, `rich_presence_kv`, `game_device_type`, `game_os_type`. No game name |
| `IPlayerService/GetRecentlyPlayedGames/v1` | OK |
| `store.steampowered.com/api/appdetails?appids=<id>&filters=basic` | OK without any token; gives the name |

With a game running, my own entry and a friend's both carried `game_id` (and rich presence). `persona_state` values seen:
0 offline, 1 online, 3 away, 4 snooze (absent when 0). Avatars are
`https://avatars.fastly.steamstatic.com/<sha_digest_avatar>_medium.jpg` (`_full` for 184 px).

## Not resolved

- **Renewal.** `GenerateAccessTokenForApp` with the refresh token answered eresult 15 (access denied), but only after a
  revoke attempt, and with a web-browser-platform token. Untested: renewal before any revoke, and with
  `platform_type=1` (Steam client) or 3 (mobile app). The provider is not viable if the user must scan every day, so this
  is the first task of `steam-provider`; SteamKit2 is the fallback.
- **Revoke.** `RevokeRefreshToken` with `token_id` (the refresh token's `jti`), `steamid`, `revoke_action=1` answered
  eresult 8 (invalid parameter). The parameters need finding (node `steam-session` and SteamKit2 do it) so that
  Disconnect really ends the session. Until then the user removes the device in the Steam app.
- **The nine friends** missing from `GetPlayerLinkDetails`: maybe a batch limit or deleted accounts.
- Rate limits for polling `GetPlayerLinkDetails` once a minute for ~100 ids are unknown; once a minute was not tested
  over hours.

## Renewal and revoke, resolved (2026-11-13)

Tested on the owner's account with a throwaway script (tokens deleted afterwards).

| Sign-in `platform_type` | Refresh token audience | Friends calls with the access token | `GenerateAccessTokenForApp` | Revoke |
|---|---|---|---|---|
| 1 (Steam client) | `client, web, renew, derive` | works | **fails**, eresult 15 (63 once) with and without `renewal_type` | fails, eresult 15 |
| 3 (mobile app), `website_id=Mobile` | `web, renew, derive, mobile` | works (access token audience `web, mobile`, 24.3 h) | **works**, eresult 1, with or without `renewal_type` (0 or 1); **no rotated refresh token** comes back | works (below) |

- **Use `platform_type` 3.** Renewal: `POST IAuthenticationService/GenerateAccessTokenForApp/v1/` with form `refresh_token`, `steamid` (the
  token's `sub`); no key, no extra auth. The refresh token lives about 210 days and is not rotated, so the user reconnects about every
  seven months (the connected readings say "sign-in expired").
- **Revoke:** `POST IAuthenticationService/RevokeRefreshToken/v1/?access_token=<access token>` with form `refresh_token`, `steamid`
  answers eresult 1, and renewal with that token fails with eresult 15 afterwards. The earlier `token_id` (the `jti`) +
  `revoke_action` forms answer eresult 8. The earlier "eresult 15 after a revoke attempt" was a revoke that had worked.
  A platform-1 session cannot be revoked this way (eresult 15): the Steam app's list is the only way to end one.
- `GetPlayerLinkDetails` for 88 friends: 78 answered (10 missing), 2 playing at the time. Rate limits over hours are still untested (task 1.3).
